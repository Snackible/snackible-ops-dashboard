INTEGRATION GUIDE - SNACKIBLE OPERATIONS DASHBOARD
==================================================

Written for another engineer or AI agent who has NO access to this codebase and needs to
integrate with this dashboard (for example from a CEO or overview dashboard). Everything below
was taken from the source code, or from responses observed on 6 October 2026. Anything that could
not be confirmed is marked UNVERIFIED.

READ THIS FIRST
---------------
  1. The integration surface is   GET /api/metrics   (section 4.2). It is read-only, FREE to call,
     needs no AI, and returns the same numbers the dashboard shows, as small stable JSON.
     STATUS: this route exists in the repository but may NOT be deployed yet. Check with
     the first curl in section 10. If it answers 404, it has not been deployed.
  2. Two other routes, /api/claude and /api/gemini, are AI proxies that COST REAL MONEY and have no
     authentication. Do not call them. They are not data endpoints.
  3. The legacy Apps Script feed (section 4.6) is unreliable and is only still used for the
     Shopify B2C tab. Do not build on it.
  4. Time zone: everything is UTC. Periods are bucketed by PO date. A week is Monday to Sunday.

4. ENDPOINTS
============

The deployment serves one web page and three API routes.

4.1 GET /   (the web app)
-------------------------
  Purpose    Returns the single-page application HTML (200, text/html). The page loads JavaScript,
             which then calls Google directly. There is no data in the HTML.
  Not for    Scraping.

4.2 GET /api/metrics        read-only, free, the integration endpoint
----------------------------------------------------------------------
  Purpose    Returns the dashboard's numbers for a chosen period, ready to display, plus the previous
             period for comparison. Reads the Google Sheet server-side and calculates with the same
             code as the dashboard.
  Auth       NONE by default: the route is OPEN to anyone who knows the URL, exactly like the dashboard,
             and needs no header. (If the owners ever set the environment variable METRICS_TOKEN, every
             request must then send it as "Authorization: Bearer <token>" or "x-api-key: <token>", and a
             missing or wrong token gives 401. As of this writing no token is configured.)
  Methods    GET and HEAD. OPTIONS returns 200 (CORS preflight). Anything else gives 405.

  Query parameters (all optional)
    period    one of: daily, weekly, monthly, mtd, custom.
              OMITTED: returns the index (see "Index response" below).
    key       The period key from section 3.2. Omitted means the newest period that has orders.
              Ignored for mtd and custom.
    start     YYYY-MM-DD. Required when period=custom.
    end       YYYY-MM-DD. Required when period=custom. Must not be before start. Range at most 400 days.
    detail    kpis (default) or full. full adds a field "block" holding the dashboard's complete
              calculation for that period (about 80 KB for a month; fields defined in section 5.2).
    refresh   1 or true asks for a fresh read of the sheet instead of the 5-minute cache. It is only
              honoured when the cache is older than 30 seconds, so it cannot be used to hammer Google.

  Common field   meta (present on every response that got as far as loading data, including 400 and 404;
                 absent on 401, 405 and on 5xx load failures)
    meta.generated_at                 string, ISO 8601 UTC. When the sheet was last read.
    meta.cache_age_seconds            integer. Seconds since generated_at.
    meta.stale                        boolean. true means a refresh failed and the last good data is being
                                      served (HTTP status is still 200).
    meta.source                       string, always "google-sheets".
    meta.timezone                     string, always "UTC".
    meta.rows_read                    integer. Order rows read (rows with a non-blank Ref No).
    meta.rows_excluded_future_po_date integer. Rows left out of period views because the PO date is after
                                      today (usually a typo). 37 on 6 Oct 2026.
    meta.rows_excluded_no_po_date     integer. Rows left out because they have no usable PO date (blank or
                                      unparseable). 847 on 6 Oct 2026.

  Index response   (no period parameter)   HTTP 200
    periods.monthly  array of strings, newest first, for example ["Oct 2026","Sep 2026",...]
    periods.weekly   array of Monday dates, newest first
    periods.daily    array of dates, newest first
    latest.monthly / latest.weekly / latest.daily   { key, kpis } where kpis has only orders, gmv, fill_pct,
                     rto_pct. latest.weekly also has start and end (Monday and Sunday).
                     A type is omitted from "latest" only if it has no data.

  Period response   (period given)   HTTP 200
    period.type        string, the period type you asked for.
    period.key         string. Present for daily, weekly and monthly. Absent for mtd and custom.
    period.start       string YYYY-MM-DD. Present for weekly (Monday), mtd and custom.
    period.end         string YYYY-MM-DD. Present for weekly (Sunday), mtd and custom.
    period.is_latest   boolean. Present for daily, weekly and monthly. true if it is the newest period.
    kpis               object, defined below.
    previous           null (for mtd, custom, or the oldest period) or { key, kpis } for the next older
                       period of the same type. Its kpis has only orders, gmv, fill_pct, rto_pct.
    change_pct         null (same cases) or { gmv, orders }: percent change from previous to current, one
                       decimal. Either value is null when the previous figure is 0.
    block              object. Only present when detail=full.

  kpis fields
    orders                  integer. Rows in the period that are not status Duplicate.
    gmv                     number, rupees, 2 decimals. Sum of Invoice Value (invoiced, not ordered).
    order_value             number, rupees. Sum of Order Value.
    fill_pct                number 0-100, one decimal. Invoiced quantity divided by PO quantity, only over rows
                            that have a PO quantity, capped at 100. It is 0 (NOT null) when the period has no
                            PO quantity at all.
    value_fulfilment_pct    number 0-100 or null (null when order_value is 0). Invoice value divided by order
                            value, capped at 100.
    rto_pct                 number, one decimal. Rows with status RTO divided by orders.
    dn_value                number, rupees. Sum of DN Value (discrepancy / debit-note value).
    delivered_pct           number or null. Delivered rows divided by ALL status rows including Duplicates.
    tat_days.po_to_dispatch        number or null. Average days from PO date to actual dispatch.
    tat_days.dispatch_to_delivery  number or null. Average days from actual dispatch to actual delivery.
    tat_days.po_to_delivery        number or null. Average days from PO date to actual delivery.
                            (null means no row in the period had both dates, which is normal for the
                            newest, still-open period.)
    statuses                object, status name to row count, including Duplicate (values in section 5.1).
    channels                array of { channel (string), gmv (number), po_qty (integer), invoiced_qty (integer),
                            fill_pct (number or null) }, sorted by gmv descending. fill_pct is null for
                            channels with no PO quantity (B2B, GT, MT and Amazon never have one).
    top_states              array of up to 5 { state (string), gmv (number) } by gmv descending. A state of
                            "Unmapped" means the location could not be matched.

  Errors   (all JSON { "error": "..." })
    400  Unknown period. Body also has "allowed": ["daily","weekly","monthly","mtd","custom"].
    400  period=custom without valid start and end; start after end; range over 400 days.
    401  Unauthorized (METRICS_TOKEN is set and the token is missing or wrong).
    404  No such period key. Body also has "available": up to 24 valid keys, newest first.
    404  No data for that period type.
    405  Method not allowed.
    500  No Google Sheets API key on the server.
    502  Google Sheets returned an error (message passed through) and no earlier data was cached.
         If earlier data WAS cached the route returns 200 with meta.stale true instead.

  Caching  Data is cached in memory inside each function instance for 5 minutes; instances are not
           shared, so two calls can briefly show different generated_at values. Response headers:
           "Cache-Control: public, s-maxage=300, stale-while-revalidate=60" when METRICS_TOKEN is not set,
           and "private, max-age=60" when it is. Every response also carries "X-Robots-Tag: noindex".
  Speed    Measured locally against the real sheet: first call about 2 seconds (it reads and calculates
           the whole tab), later calls about 1 millisecond. Deployed timings are UNVERIFIED.
  Not for  Fast polling (5 minutes is the freshest it can be anyway), or row-level data (it returns
           aggregates only).

4.3 POST /api/claude        COSTS REAL MONEY - DO NOT CALL
---------------------------------------------------------
  Purpose    Server-side proxy to the Anthropic Messages API for the "AI analysis" panel.
  Auth       None. Anyone who can reach the URL can spend the Anthropic credit.
  Methods    POST works, OPTIONS 200, anything else 405.
  Body       JSON: messages (array of { role: "user" or "assistant", content: string }, required),
             system (string, optional), max_tokens (integer, default 1000). A "model" field is
             IGNORED; the function always uses "claude-sonnet-4-6". An extra "json" field is ignored.
  Success    HTTP 200 with the unmodified Anthropic response; the text is at content[0].text.
  Errors     405 { "error": "Method not allowed" }; 500 { "error": "No Claude API key set. Add CLAUDE_API in Vercel and redeploy." };
             502 { "error": "<Anthropic message>" }; 500 { "error": "<exception message>" }.
  Not for    Anything. Every successful call is billed per token.

4.4 POST /api/gemini        COSTS REAL MONEY - DO NOT CALL
----------------------------------------------------------
  Purpose    Same job as /api/claude using Google Gemini (the Claude/Gemini toggle on the AI panel).
  Auth       None.
  Methods    POST, OPTIONS (200), anything else 405.
  Body       JSON: messages (array as above, required), system (optional), max_tokens (the function uses
             max(max_tokens or 1000, 4096), so never below 4096), json (boolean; true asks for JSON-only).
  Success    HTTP 200  { "content": [ { "type": "text", "text": "<reply>" } ] }
  Errors     405 { "error": "Method not allowed" };
             500 { "error": "No Gemini key is set on the server. Add Gemini_Api_Key in Vercel and redeploy." };
             429, 503 or 504 passed through unchanged with { "error": "<Gemini message>" } (temporary,
             retry later); 502 { "error": "..." } for every other failure, a blocked prompt
             ("Blocked by Gemini: <reason>") or an empty reply; 500 { "error": "<exception message>" }.
  Key failover   Tries every configured Gemini key in name order. On 429 (quota or rate limit) or a rejected
                 key (401, 403, "API key not valid") the same request moves to the next key, and the bad
                 key is skipped for 10 minutes (quota) or 1 hour (invalid). The skip list is in memory in
                 one function instance. A busy model (503) does not trigger failover.
  Not for    Anything.

4.5 Google Sheets API v4 (called directly by the dashboard's browser, not by this server)

  Notes      UNFORMATTED_VALUE returns numbers as numbers and dates as the sheet's text (dd-mm-yyyy) or as

  Not for    Integrations. Use /api/metrics instead. One call returns the whole tab (several MB).

5. VALUE DEFINITIONS
====================

5.1 Order status (normalised from the STATUS column, case-insensitive, by prefix)
--------------------------------------------------------------------------------
  Delivered   starts with "deliver"
  In-Transit  equals "intransit" once spaces and hyphens are removed (In-Transit, in-transit)
  Pending     starts with "pending"
  Hold        starts with "hold"
  Cancelled   starts with "cancel"   (includes "Cancelled PC")
  RTO         starts with "rto"      (returned to origin; this INCLUDES "RTO - Delivered" and
              "RTO - Intransit", so those count as RTO, not as Delivered)
  Duplicate   starts with "dup"      (excluded from orders and every total)
  Kunafa      starts with "kunafa"
  Other       any non-blank value not matched above (for example "Expired", "Internal PO")
  (blank)     counted under "Other" in status tallies

5.2 The full block (what detail=full returns under "block", and what the dashboard calculates)
---------------------------------------------------------------------------------------------
  A block is one period. It is derived at request time. NOTHING is stored.

  orders             rows not status Duplicate
  gmv                sum of Invoice Value
  total_order_val    sum of Order Value
  total_inv_val      sum of Invoice Value (same as gmv)
  dn_value           sum of DN Value
  statuses           status name -> row count, INCLUDING Duplicate rows
  avg_fill           percent, one decimal (see fill_pct above)
  rto_pct            percent, one decimal
  avg_proc_tat       average days PO date to Act Dispatch
  avg_tran_tat       average days Act Dispatch to Act Del
  avg_total_tat      average days PO date to Act Del
                     (a row only counts when both dates exist and the difference is zero or more;
                     the averages are 0 when there is no data)
  channels           channel -> sum of Invoice Value
  channel_fill       channel -> { po, inv, rate (0 to 1), short } with short = max(0, po - inv)
  channel_val        channel -> { po_val, inv_val, rate }
  order_types        platform bucket -> sum of Invoice Value
  locations          STATE -> sum of Invoice Value
  cities             CITY  -> sum of Invoice Value
  city_gmv           state -> city -> sum of Invoice Value
  state_fill         state -> { po, inv }
  city_fill          state -> city -> { po, inv }
  skus               SKU name -> units ordered
  state_sku, city_sku, channel_sku   SKU units by state, city or channel
  daily_inv          dispatch date (YYYY-MM-DD) -> channel -> invoiced units, by each row's Act Dispatch
  couriers, channel_tat, state_tat   name -> { orders, avg_proc_tat, avg_tran_tat, avg_total_tat, avg_tat,
                     on_time_pct } with on_time_pct the share delivered within 7 days of PO date

5.3 Raw sheet fields versus derived fields
------------------------------------------
  Raw (typed by people in the sheet): Ref No, PO Date, PO, Channel, Location, State, Order Value, PO Qty,
  Invoice Qty, Invoice Value, Act Dispatch, Courier, Act Del, STATUS, DN Value, and the per-SKU quantity
  columns.
  Derived at calculation time (never stored): everything in 5.2, plus city (from Location), platform bucket
  (from channel), state when the sheet's State is blank, the delivered log, the SKU value split, the
  "rows excluded" counts, and every field returned by /api/metrics.

5.4 Delivered log (dashboard only; not returned by /api/metrics)
---------------------------------------------------------------
  One item per row with status Delivered AND an Act Del date, newest first: po_date and date as "dd-mm-yyyy",
  ref, po, channel, val (Invoice Value), _time (delivery date, milliseconds since the Unix epoch). The
  dashboard groups it by DELIVERY date, unlike every other view which groups by PO date.

5.5 SKU analysis (dashboard only; not returned by /api/metrics)
--------------------------------------------------------------
  Only five channels are counted: Hot - Blinkit as "Blinkit", KK - Zepto as "Zepto", Scootsy - Swiggy as
  "Swiggy", BB, Amazon. The "value" view splits each row's Order Value across its SKUs in proportion to units
  (an estimate, not a real per-SKU price).


6. RECOMMENDED INTEGRATION PATTERN
==================================

One clear default: READ-ONLY, API-ONLY, SERVER-TO-SERVER, THROUGH /api/metrics.

  1. Call GET /api/metrics from your own backend, never from end users' browsers. No credentials are
     needed today. If a METRICS_TOKEN is later introduced, send it as "Authorization: Bearer <token>".
  2. For a headline card use  ?period=weekly  or  ?period=monthly  (the newest period) and read kpis,
     previous and change_pct. For "this month so far" use  ?period=mtd.
  3. Poll no more often than every 5 minutes. The route caches for 5 minutes, so faster polling returns the
     same numbers. Never loop on refresh=1.
  4. Treat meta.stale = true as "numbers are from the last good read", and show meta.generated_at to users.
  5. Display tat_days and value_fulfilment_pct as "no data" when null. Do not show them as 0.
  6. Do NOT read the Google Sheet or the database yourself. The sheet needs the normalisation rules in section
     9 to match the dashboard; /api/metrics already applies them. There is no database.
  7. Do NOT call /api/claude or /api/gemini, and do NOT use the Apps Script feed. (Shopify B2C figures exist only
     in the feed; if you need them, say so and ask for a dedicated route.)


7. DATA FRESHNESS AND FALLBACK BEHAVIOUR
========================================

  Source         The Google Sheet, read through the Sheets API.
  /api/metrics   Calculated server-side, cached 5 minutes in memory per function instance. After a failed
                 refresh it serves the last good data with meta.stale = true. If it has never loaded data it
                 answers 502 (Google error) or 500 (no key). There is NO demo data.
  Dashboard      The browser loads the whole tab on open and reloads silently every 5 minutes while the tab is
                 visible (user can choose manual only, or press Refresh). A catch-up refresh runs when a hidden
                 tab becomes visible after being stale. If a background refresh fails it keeps the last good
                 data and says so in the footer.
  Worst-case staleness   About 5 minutes plus however long ago a person last edited the sheet (the sheet is
                 filled in by hand).
  "Is it real" flag   meta.stale on /api/metrics. Nothing else falls back, so nothing else needs a flag.
  Legacy feed problems (observed 6 Oct 2026, do not rely on it)
                 - weekly was empty.
                 - delivered_log was truncated at 2000 items and its po_date values had the year 0001.
                 - Totals differ from the sheet from June 2026 onward. Orders by PO month: Jul 2026 feed 779
                   versus sheet 964; Sep 2026 feed 872 versus sheet 1075. March matched exactly (744). The
                   cause is UNVERIFIED because the script source is not available.
                 - channel names appear in several cases (HOT and Hot, kk and KK) as separate keys.


8. SECURITY AND ACCESS NOTES
============================

  Dashboard login  NONE. Anyone with the URL can open it and see every number.
  /api/metrics     OPEN by design (no token configured), like the dashboard itself. Anyone who finds the URL can
                   read the aggregates. It exposes aggregates only: no row-level data, no personal data. The
                   optional METRICS_TOKEN switch exists (Bearer or x-api-key, compared in constant time) if
                   the owners later want to lock it. Never put a token in browser code.
  AI routes        /api/claude and /api/gemini have NO authentication, no rate limit and no spend cap. Any caller
                   can spend Anthropic or Google credit. Set provider-side spend limits.
  CORS             All three routes answer OPTIONS with 200 and set Access-Control-Allow-Origin only when the
                   request Origin is on an allow-list: https://adityasanghavi-sys.github.io,
                   https://snackible-ops-dashboard.vercel.app,
                   https://snackible-ops-dashboard-new.vercel.app, plus anything in ALLOWED_ORIGINS.
                   /api/metrics allows methods GET and OPTIONS and headers Content-Type, Authorization,
                   x-api-key. The AI routes allow POST and OPTIONS and header Content-Type.
                   IMPORTANT: on the deployed site on 6 Oct 2026 the production domain was NOT yet in the AI
                   routes' allow-list; the repository now includes it, but whether the deployed copy has it is
                   UNVERIFIED until this change is deployed. Server-to-server callers (the recommended pattern)
                   are not affected by CORS at all. Browsers on a third-party origin must be added to
                   ALLOWED_ORIGINS.
  Secrets          VITE_GOOGLE_API_KEY is compiled into the public JavaScript and readable by any visitor;
                   restrict it to the Sheets API and this site's referrers in Google Cloud.
                   GOOGLE_SHEETS_API_KEY, METRICS_TOKEN, CLAUDE_API and the Gemini keys exist only as server
                   environment variables.
  Pasted keys      A user can paste a personal Gemini key into the AI panel. It stays in that browser tab
                   (sessionStorage) and is used for direct browser-to-Google calls only.
  Public identifiers   The spreadsheet ID and the Apps Script URL are in a public repository. Treat the sheet
                   as readable by anyone who finds them.
  Never expose publicly   Any key or token, or the contents of .env.local.
  Data sent to AI providers   Each AI request sends the selected period's aggregated figures to Anthropic or
                   Google. /api/metrics sends nothing to any AI provider.


9. GOTCHAS AND DESIGN DECISIONS
===============================

  Row selection
  - Only rows with a non-blank Ref No count. About 35 percent of the tab is blank padding.
  - Rows with status Duplicate are excluded from orders and every total, but still counted in the "statuses"
    map.
  - Rows with no usable PO Date (847 on 6 Oct 2026) are excluded from every PERIOD view (daily, weekly, monthly,
    mtd, custom). They still appear in the dashboard's delivered log.
  - PO dates AFTER TODAY are excluded from period views and counted in rows_excluded_future_po_date (37 rows on
    6 Oct 2026, almost all dated 23-10-2026 while their reference numbers read Sep26-8xx, so they look like a
    mistyped month). The cutoff is the current time plus 36 hours. Dates before 1 Jan 2024 and unparseable
    dates (for example 04-06-0206) are treated as missing. 2027 dates were seen and are also excluded.
    Consequence: months can look smaller than reality until the sheet's dates are corrected.
  Dates and time zones
  - Sheet dates are text in day-month-year order (dd-mm-yyyy), parsed as UTC midnight.
  - /api/metrics is UTC throughout: "today", mtd, and the weekly Monday. The dashboard UI labels convert with
    the viewer's local time zone and its Month-to-date starts on the first day of the viewer's LOCAL month and
    ends on today's UTC date, so the dashboard's MTD can differ from /api/metrics?period=mtd for a few hours
    around month boundaries.
  - The legacy Shopify feed keys weeks by the SUNDAY that starts them; everything else uses Monday.
  Fill rate
  - PO Qty is 0 for B2B, GT, MT and Amazon rows (invoice quantity but no PO quantity). Those rows are left out
    of every fill figure, otherwise invoiced units would be counted against zero ordered and fill would exceed
    100 percent. They still count in gmv and orders. That is why their channels[].fill_pct is null.
  - fill_pct is by quantity. value_fulfilment_pct (invoice value over order value) is separate.
  - Open (current) periods show low fill and few TAT values because orders are still moving.
  State and city
  - The sheet's State column is blank on roughly two thirds of rows. When blank, the state is derived from
    Location with a keyword list (for example "Bengaluru B3" gives Karnataka, "Dasna D3" gives Uttar Pradesh).
    Anything unmatched becomes "Unmapped".
  - City is derived from Location by removing everything after " - ", a trailing warehouse code such as "M10"
    or "B3", or a trailing number, then capitalising ("Mumbai M10 - Feeder Warehouse" gives "Mumbai").
  Status quirks
  - "RTO - Delivered" counts as RTO, not Delivered. The delivered log only includes status Delivered.
  - Free-text statuses such as "Expired", "Internal PO" and even "Wednesday" occur and land in "Other".
  Columns and SKUs
  - Columns are matched by header NAME (case-insensitive, line breaks and repeated spaces collapsed, first
    match wins), so column order can change safely but renaming a header breaks it.
  - Header names used: Ref No, PO Date, PO, Channel, Location, State, Order Value, PO Qty, Invoice Qty,
    Invoice Value, Act Dispatch, Courier, Act Del, STATUS, DN Value.
  - SKU quantity columns are every column with a non-blank header AFTER the column titled "Total Weight"
    (about 52). Roughly 15 percent of orders have no SKU split, so SKU totals undercount against GMV.
  - Anything beyond column CZ is not read.
  Numbers
  - GMV is INVOICED value. An order with Invoice Value 0 or blank adds nothing to gmv but still counts in orders.
  - The UI formats in lakh and crore (14.7L). The API returns plain numbers in rupees.
  Parity with the old feed
  - The sheet-based calculation is a reimplementation; definitions were inferred from the old dashboard and
    checked only approximately. Fill rates agreed within a couple of points for most months; orders and GMV
    differ from June onward (section 7). Never expect an exact match with the legacy feed.
  What is stored where
  - Nothing is stored server-side: no database, blob store or file storage. The only server memory is the
    5-minute cache in /api/metrics and the key skip list in /api/gemini, both lost on restart.
  - Browser only: localStorage "theme" (light or dark; absent means follow the system), "auto-refresh" ("off"
    when manual only), "ai-provider" ("gemini" or "claude"); sessionStorage "gemini-session-key".
  Scheduled jobs and admin routes
  - None. No cron, no admin endpoints, no webhooks. (UNVERIFIED for the Apps Script feed, which may have its
    own triggers.)
  Cost, rate and safety summary
  - COSTS REAL MONEY: POST /api/claude, POST /api/gemini. Never on a loop or a poll.
  - Free: GET /api/metrics (one Google Sheets read per cache refresh).
  - SLOW: every Apps Script call except the plain one takes 15 to 21 seconds, and ?action=custom without dates
    hangs.
  - Google Sheets API has per-minute quotas per project (check Google's current limits for your key).


10. EXAMPLE REQUESTS
====================

All of these are read-only and free unless marked. The route is open, so no header is needed. If a
METRICS_TOKEN has been introduced since this was written, add the header shown in the "Alternative: sending a token"
example. A 404 on the first request means /api/metrics is not deployed yet.

  Index: which periods exist, and the latest of each
      curl -s https://snackible-ops-dashboard-new.vercel.app/api/metrics

  Latest week, with comparison to the week before
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=weekly"

  A specific week (any date inside it works)
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=weekly&key=2026-09-17"

  A specific month (either form works)
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=monthly&key=2026-09"
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=monthly&key=Sep%202026"

  One day
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=daily&key=2026-09-17"

  This month so far
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=mtd"

  A custom range (inclusive, at most 400 days)
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=custom&start=2026-09-01&end=2026-09-30"

  Everything the dashboard calculated for a month (about 80 KB)
      curl -s "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=monthly&key=2026-09&detail=full"

  Alternative: sending a token (only if one has been set)
      curl -s -H "x-api-key: <TOKEN>" "https://snackible-ops-dashboard-new.vercel.app/api/metrics?period=monthly"
      (only needed if a METRICS_TOKEN has been set)

  Check the app is up
      curl -s -o /dev/null -w "%{http_code}\n" https://snackible-ops-dashboard-new.vercel.app/

  Inspect CORS for your own origin (a preflight; no data and no paid call involved)
      curl -s -i -X OPTIONS -H "Origin: https://your-dashboard.example.com" \
           -H "Access-Control-Request-Method: GET" \
           https://snackible-ops-dashboard-new.vercel.app/api/metrics
      (look for Access-Control-Allow-Origin; if absent, browsers on that origin cannot call it)

  Confirm an AI route exists WITHOUT spending money (GET is rejected before any paid call is made)

      (expected: HTTP 405  {"error":"Method not allowed"})
